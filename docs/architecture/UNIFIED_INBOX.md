# Unified inbox

The existing Vue WorkspaceView remains the inbox and Web Chat UI. `/api/inbox` returns tenant-owned conversations with contact, channel, assistant, assigned agent/user, language, status, escalation, last message and timestamp. Server filters accept channel, assistant_id, status, locale, from_date and to_date (aware timestamps). The dashboard provides channel, assistant, status, language and date filters, history, localized delivery state and quarantined attachment metadata. Lists remain unpaginated in this development topology.

Operators may take over, reply, return control and close through authenticated `/api/conversations/{id}/control` and `/human-reply`. Both require approve permission and explicit confirmation; viewers cannot write. Takeover records the operator and pauses agent replies, while customer messages continue to persist. Pending automatic response jobs are cancelled on takeover. Connected operator replies use the same outbox and originating endpoint; reused event IDs with changed reply text are rejected. Direct Web Chat retains its existing mock dispatch and cached-event duplicate handling. Resume restores the receptionist; closed conversations cannot resume. New inbound messages to closed provider threads start a fresh conversation.

Customer human requests in the default policy cause a permission-checked executor escalation and appear assigned/escalated in the shared inbox. A tenant's configured escalation keyword policy retains its existing approval behavior. Agent/tool permission revocation is respected; escalation cannot bypass the registry. No external operator notification/email is sent merely because a conversation is assigned.

Web Chat keeps the shared `/api/conversations` and `/messages` APIs. Background history/approval refresh runs every two seconds for the open inbox, with visible busy/error states. The deterministic mock provider returns whole responses and advertises no token-stream capability. Real token streaming remains an optional provider integration; synthetic voice has its existing bidirectional stream. File upload is tenant/conversation-scoped, 2 MB, quarantined and attached by storage ID. HTML is never rendered as customer markup.

Channel configuration reuses existing routes and adds masked credential forms for mock/SMTP/Meta/Twilio, account identifiers, draft/live policy and attempt quotas. Cards show mock or LIVE_UNVERIFIED, enabled/disabled/error, webhook state, supported languages, capabilities and last error; no connection is labelled production-connected based on a mock signature check.

Browser smoke verifies Bulgarian/English chat booking, takeover/reply/resume, existing voice booking/controls and mobile layout. Production inbox pagination, push subscriptions, operator workload routing and notification delivery to on-call staff remain scale integrations.
