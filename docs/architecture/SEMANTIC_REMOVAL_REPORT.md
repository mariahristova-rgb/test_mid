# Semantic removal report

Owner approved the Phase 1 removal plan and all implementation phases in this chat on 2026-10-08. Work remained inside test_mid. The original repository was not opened or modified. No confidential disclosure or patent document was incorporated into code/docs/history.

Exact removed source/generated paths are listed in [REMOVED_FILES.json](REMOVED_FILES.json): 2,276 paths at the reviewed removal stage, including compiled caches and stale frontend bundles. This records removal of the copied versions; some paths now contain replacement assistant code. This is a filename manifest, not copied implementation content. The initial application was untracked and the branch had no commits, so the manifest is the removal evidence; there is no historical Git diff or rollback commit. Changes remain reviewable as the final source tree on `codex/phase1-repository-audit`.

Removed: kernel and nested semantic assertion/identity/knowledge/evolution/reflection/self-healing/discovery implementations; belief/trust/reasoning and dedicated semantic events; graph/ontology/metamodel/intelligence/migration mapping/reconciliation/repair runtime; coupled data-platform workers/routes; kernel-backed local AI/semantic memory/service bridge and old domain agents; dedicated frontend routes/views/clients, help/demo material, old generated assets and coupled tests. Old Spark/JVM, connector SDK and billing runtime dependencies were pruned from the active manifest.

Retained/refactored: Vue/Vite/Tailwind, generic visual tokens/layout conventions and EmptyState; Auth0 SPA SDK and backend verified RS256/JWKS adapter; dependency-free rate limiter; provider-neutral generation DTOs; source-secret scanner and tests; non-root container and build/header safeguards. Identity, authorized requests, bilingual chat/configuration and tenant history were reconnected to the independent assistant composition. Generic queues, encrypted secret handling and tenant persistence were implemented against a new synthetic baseline because the old composition/storage was coupled to semantic/data-platform services.

Review decisions: the old unregistered platform_core scaffold was removed after confirming missing database.session imports, invalid absolute paths and circular service/repository wiring. Its user/tenant/RBAC responsibilities now run through the active new module. The shared Spanner schema, data-transfer code and old storage factory were not carried into the new runtime; retaining them would keep irrelevant schema/SDK/dependency closures. Generic vector/RAG components were optional for this MVP and are not installed, rather than being reconstructed as a semantic memory system. Existing source names alone were not used as evidence of prohibited behavior: audit imports/responsibility determined the cut points.

Runtime separation: deployed `backend.api.app` and compatibility `semantic_os.main` both compose the new assistant app. No import into the original namespace, no semantic DI singleton, no semantic route registration and no semantic UI navigation remain. Generic retained provider DTO comments mentioning possible search are not executable semantic services. Docs/manifest retain historical module names as removal evidence; directory name semantic_os remains for package compatibility.

Data effects: no legacy database, applied migration, env file, encryption key, workspace backup or real fixture was deleted. New fresh-development migrations are versions 1 and 2. Runtime workspaces and credentials are ignored and excluded from Docker context. Future disposition of existing proprietary stored objects/data is an owner decision outside source removal.

Validation: see [IMPLEMENTATION_STATUS](IMPLEMENTATION_STATUS.md) for exact observed command results. Static import checks, clean app import/start, backend acceptance tests, bilingual UI resource tests, Vue typecheck/lint/build and redacted source scans validate the local foundation. No live integration, speech evaluation, Docker deployment or legal clearance is implied. Uncertain IP boundaries remain an owner/legal review matter; technical removal is not a legal opinion.
