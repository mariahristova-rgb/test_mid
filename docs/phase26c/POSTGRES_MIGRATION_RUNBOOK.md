# Migration and restore runbook
1. Stop creation admission and drain approved pending work. Keep uncertain provider jobs and external IDs; never blindly replay writes. Record source revision and encrypted backup/checksums.
2. Target a new empty PostgreSQL database/schema only. Bootstrap explicitly with PostgresStore(dsn,migrate=True); ordinary API startup requires migration version1 already present. Unknown/nonempty legacy targets fail closed. Future schema changes require a new reviewed migration, never editing an existing production version in place.
3. Map SQLite migration versions1–5, tenant composite keys, JSON data, reception order and ledger immutability. Import in a transaction with validated deferred foreign keys. No real data/token migration was authorized here.
4. Run scripts/phase26c_migration_rehearsal.py only on its labelled loopback fixture. It imports representative two-tenant snapshots, compares 50 table checksums, runs native pg_dump/pg_restore into a new database, checks restored checksums and ledger trigger, and verifies original SQLite integrity. Actual result PASS_LOCAL_RUNTIME. Native PostgreSQL functions/indexes/triggers survive this restore.
5. Validate approvals/jobs/reservations, next reception cursor, tenant isolation and GET-only uncertain recovery before switching traffic. Rehearsal source is synthetic and remains unchanged; it is not a zero-loss customer cutover receipt. Generic production import tooling, identity cursor preservation across arbitrary snapshots and reconciliation of writes during a cutover remain BLOCKED.
6. Rollback before traffic switch uses the unchanged source SQLite backup. After PostgreSQL accepts new writes, switching to an old SQLite snapshot would lose data: stop admission, export/reconcile the delta and obtain reviewed rollback approval. Do not drop production schemas or run destructive down migrations.

Application BackupManager remains SQLite-only and returns unconfigured for PostgreSQL. Native Cloud SQL PITR/pg_dump restore needs staging verification and an operator-controlled encrypted destination before GO. Fixture cleanup verifies exact container label/loopback bindings; all synthetic schemas/databases are removed by the scripts.
