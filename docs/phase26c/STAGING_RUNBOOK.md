# Staging deployment and recovery runbook
No apply authorized. Before deployment: review exact branch/images, project/region/residency, IAM/auth, TLS/DSN and secret versions, model manifest, private access routing, budget ceiling and kill owner. Validate terraform using backend=false; run a reviewed plan only after configuration is complete. Never put tokens/secrets in tfvars, state logs or repository.

Order: approved private network/SQL → encrypted backup and restore rehearsal → native schema bootstrap/import on new target → application plan/auth provisioning → API readiness → private model artifact/load checks → synthetic BG/EN journey → separately approved provider test. Keep customer OAuth/writes and billing disabled until their own receipts pass. CloudRun startup /health/ready fails closed on missing auth/encryption/plans; model /health probe must match its pinned server image.

Observe redacted structured error codes/correlation IDs, SQL pool waiters/latency, job pending/uncertain state, provider timeouts, 5xx alarm and actual spend. Notifications have no recipient configured; configure only approved operators. Test kill switch by disabling new assistant/provider admission, revoke invocation grants if needed, then deploy the previous pinned image with a compatible schema. SQL and retained audits/uncertain jobs survive code rollback.

Before data rollback: stop writers, backup, reconcile external IDs, restore into a NEW instance, checksum and tenant-verify, then explicitly switch DSN. Never automatically replay uncertain external writes. Deletion protection prevents accidental SQL/bucket destruction; an approved teardown retains backups but storage still costs money. Cloud SQL, model, private routing, file broker, alert delivery and kill automation have NOT been exercised in cloud. No staging GO.
