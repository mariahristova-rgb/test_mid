# End-to-end voice flow and verification boundary

Implemented path: SIP caller 1001 → Asterisk PJSIP extension 2000 → ARI Stasis `testmid-voice` → private ExternalMedia PCMU/RTP → `RTPAudioTransport` → existing `VoiceRuntime`/energy VAD → persistent CPU faster-whisper small → existing `Orchestrator` → Receptionist/Qwen structured booking intent → Task Execution/Qwen validated tool proposal → authorized mock calendar tools → local BG38/MioCodec neural voice (optional eSpeak baseline) → bandlimited 8 kHz μ-law RTP playback. Signaling/audio and individual inference stages are real-tested; complete booking journeys remain unachieved.

The SIP stack is Asterisk; no custom SIP framework or managed speech service was added. ARI uses authenticated headers, a deployment-owned private IP and trusted extension/endpoint routing. Tenant selection is never taken from caller speech or caller JSON. ExternalMedia peers are obtained through authenticated ARI and checked against the configured Asterisk IP. RTP validates version, payload type, frame length, SSRC and sequence progression; wrong peers are ignored, malformed negotiated packets/backpressure fail closed. PCMU 20 ms frames are paced on output. Local TTS is resampled from its declared rate to narrowband PCM/μ-law. Full speech-quality testing remains required.

CallSession, tenant, assistant, conversation, locale, correlation and authorized tools travel through booking handoffs. Model proposals cannot alter application-owned arguments. Availability runs before proposal; explicit confirmation is required before transactional persistence and availability revalidation. Both agents share the deployment-owned model endpoint; each turn has its own cancellation state. Duplicate message/tool events use existing persisted idempotency. Bulgarian never silently uses an English voice.

Audio reception stays outside STT/LLM/tool workers. Queues and native engine admission are bounded. Barge-in stops obsolete packet playback and cancels the relevant model request; post-STT and pre-commit checks reject obsolete work. Disconnect closes the socket, terminates the scoped CallSession and removes owned ARI channels/bridge. HTTP/connection deadlines exist; native speech inference cannot currently be forcibly killed mid-call. Shutdown can wait for a running native inference. This remains a real-provider failure-test gate.

Privacy: recordings/transcripts default off. The existing voice manager redacts full text from message history unless explicitly configured encrypted retention is enabled; dashboard activity reflects persisted execution/appointment metadata. Model requests necessarily receive the required booking data, but request bodies/credentials/audio are not logged by these adapters.

Generic Bulgarian/English wait/failure audio is synthesized once before backend readiness. A six-second delayed acknowledgement uses cached audio without blocking RTP reception or waiting for another model request. Cached failure audio does not retry business actions or claim success. Epoch checks suppress obsolete acknowledgements/errors after barge-in. CPU deadlines remain bounded; active inference/synthesis/playback is not treated as idle caller silence. Spoken booking summaries omit web-button instructions and offer one alternative at a time, while canonical tool results remain persisted.

Known limits: batch STT/TTS rather than streaming synthesis, simple energy VAD, unverified echo/noise behavior, no implemented Asterisk human transfer, no SRTP/TLS certificate deployment in the local recipe and global SQLite serialization during model work. Native inference cannot be forcibly terminated mid-generation; bounded service admission and HTTP/turn deadlines contain it, and cached failure audio remains available. Human speech/intelligibility and full booking acceptance remain required.

The ARI design follows [Asterisk ExternalMedia documentation](https://docs.asterisk.org/Development/Reference-Information/Asterisk-Framework-and-API-Examples/External-Media-and-ARI/). Local engine calls follow [faster-whisper's local-path interface](https://github.com/SYSTRAN/faster-whisper) and [Piper's Python API](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/API_PYTHON.md).
