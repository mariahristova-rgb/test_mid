# Windows Docker local setup

Verified: Windows 11 Pro, WSL2 docker-desktop, Linux x86-64 Docker Desktop 4.54.0, engine 29.1.2 and Compose 2.40.3. Ryzen 7 5700U has 8 physical/16 logical cores. Integrated AMD graphics is not used for inference. Current Docker memory is 7.44 GiB; the requested 10 GB WSL target is provided in scripts/demo/wslconfig.example, but was not applied because restarting WSL/Docker would interrupt unrelated running containers.

From test_mid, run scripts/demo/start-local.ps1 -Build after the model cache is prepared. Stop with scripts/demo/stop-local.ps1; it stops only testmid-cpu-voice and preserves model/database directories. check-local.ps1 shows only this project's health/resources, SIP contacts and ARI applications. reset-demo.ps1 rejects running services and archives only the marked fictional tenant.

For the evaluated neural replacement, provision speech with scripts/provision_bgtts.py (see its CLI help), then run scripts/demo/start-local.ps1 -Build -NeuralVoice. The optional compose.cpu-neural.yml replaces the same TTS service; it does not add another inference service. The script verifies speech/model hashes and rejects active owned calls before changing the marked tenant's voice configuration. Neural TTS has a 2200 MiB cap and two CPU threads; aggregate limits exceed the current WSL allocation, so limits alone are not proof of memory safety. Actual concurrent usage must fit. The model loads once and TTS retains only decoder weights plus exact convolution geometry after warm reference extraction. First offline preload including hash verification took 86.913 seconds. Each image's observed package versions are recorded in requirements-stt.lock / requirements-neural-tts.lock and constrain subsequent builds. Optional package/OS security review is still a production gate.

The existing backend owns both the Voice Gateway and one SQLite database. Asterisk, Qwen, STT, TTS and frontend are separate workers/services; no duplicate DB or queue exists. Model volumes are read-only. Credentials are generated into ignored artifacts/local-demo/secrets with restricted Windows ACLs and referenced through Docker secrets; do not put them in the frontend bundle.

The internal network carries model/speech/backend traffic. A second network is required for Windows-facing loopback publications: an internal-only Docker network produced no usable host port mapping in the actual test. Publications are 127.0.0.1 only: frontend 3011, Qwen 8087, SIP UDP 5060 and RTP UDP 10000–10099. No public SIP or unauthenticated inference is configured. GPU layers are zero.

Diagnostic commands: wsl --status; wsl --list --verbose; docker version; docker info; docker compose version; scripts/demo/check-local.ps1. Do not stop unrelated containers or apply a WSL restart outside an agreed window. This is a local development recipe, not verified production deployment.
